# Brandon / Tokela / Atimal: functional change map

Public-ref snapshot: November 1, 2026. Static source/history/diff analysis only; no donor DLLs, code, Windows builds or Kenshi tests were run. PASS/FAIL results in donor messages/design notes are author reports, not independent verification.

## Scope and ancestry

- Upstream nhoral: `5a761e19a4184b42315e96ea7e92e3c1403d54db`.
- Brandon main `7fdea3f4cfd5021dca72015215c5667e00d40a89`; release/0.1.33 `cb5a3b9e5619bb4b51c817b3e367f4472a54d202`. Main is 21 commits behind release; no other public branches.
- Tokela main `5a23eef86e1a62ed96b49610058292d4edd33186`; feat/internet-smoothing `b3bd37b7e5aaed9f31c2a9a581b88d688f2a9c3e` has two further commits. Its other 33 public branches are ancestors of main.
- Atimal main `d03d6005a2bcaa6aa2fe7fde4c7e9f6b74d4acf3` is an older Tokela main; merge-kenshiduo `301d7bf75833e6a8d71aca5dc74d56d28ff9113e`. The other 26 branches, including store-add, are already ancestors of merge-kenshiduo.
- Brandon/kotetsyy share `c413ee03ad72ab74ac8445e6584b23537f59e0a7`; the 0.1.0–0.1.31 line includes shared native UI, updater, conservation, 100 Hz and merchant work. Count it once, then inspect Brandon’s independent tail.
- Atimal `c54609bf26ac39921434399afc276ca12f521f9b` merges Tokela0.54 and KenshiDuo. Parent `b529fa3` carries community work from zeroit789/jayceslesar/BorjaAres/jbaxter91, including authority redesigns; this is not merely a UI fork.
- Savas comparison base: `58514ea33538fca78e932abf44bb658d4e915236`. Similar problems were fixed in parallel with different implementations/wire formats.

[Complete branch manifest](branch-manifest.json). Local read-only research repositories/exported sources are not published here; SHAs and provenance are retained in [changes-tokela.json](changes-tokela.json).

Classes: BASE = shared ancestry counted once; PORT = adapt by function; CHOICE = choose one implementation; OPTIONAL = separate feature/policy; REUSE = supporting tests/tooling.

## Established incompatibilities

1. **Wire collisions:** Brandon tags 50 SquadName, 51 FactionRename, 52 FactionName, 53 Jobs; atimal tags 50 ProdIntent, 51 DoorIntent, 52 FurnIntent, 53 BuildIntent, 54 InvSaveFence, 55 Bounty, 56 ModList, 57 StoreAdd; Savas 52 VendorDelta, 53 VendorCash and separate JoinState. Brandon public protocol 72/private NET_DIAG73, Savas65, atimal68, Tokela59. Equal version numbers across forks do not establish compatibility. A new identity/tag registry, size/limit checks and foreign-build refusal are required.
2. **Session topology:** Brandon has four players, Savas eight, Tokela/atimal two. Owner/stale/admission/roster/tab/fence/ACK/trade/lobby state must be per player/session. One global friend state cannot be copied unchanged into an eight-player runtime.
3. **Inventory writers:** StoreAdd minting, optimistic transfers, cursor reservations, exact stock layout, vendor deltas and trader handover can count one action repeatedly. Define one operation ID and settlement mechanism after identity.
4. **World authority:** Tokela/atimal enabled cellAuth, but latest Tokela b3bd37b disables it after reported field failures. Savas split/recruit fixes and Brandon NPC mirrors use different ownership/copy predicates. Proposed initial policy is host world authority and owned player squads, with cell authority opt-in until boundary migration is proven.
5. **UI/update:** Native UI with paired updates, MyGUI F2 and main-menu lobby are alternative frontends. Select one input/focus/callback owner; configure names, URLs, Workshop item and manifests for the combined project.
6. **Saves:** Load-specific READY, inventory fence, metadata/jobs flush, atomic staging, compression, pause reason and backups form one transaction. Reconcile complete state machines rather than selecting conflicting SaveXfer files.
7. **Build/ABI:** Tokela pins KenshiLib 0.3.0; Brandon fixes headers for 0.4.0. ENet 512 KB internals and the kotetsyy GNS migration need distinct adapters. Gameplay fixes can precede transport migration, but direct ENet internals cannot be copied into GNS.

## Integration sequence and acceptance

1. Pin SHAs/provenance and select toolchain, engine version, transport, UI and capacity. Define one wire registry, session epoch and stable entity/tab keys.
2. Bring in T01/B11 build/dependency/test helpers and establish a clean baseline. Use --ignore-space-at-eol for B01 CRLF-heavy diffs; raw line counts exaggerate functional changes.
3. Adapt lifecycle/network: T15 shutdown, T03 refusal, T02 mod parity, T12 callbacks, LAN/WAN profiles and per-player state. Implement T08/A13 semantics through the transport API when using GNS.
4. Reconcile T06/A05 ownership, B04 spawn/recruit/mint guards and Savas freshness rules. Keep cell authority off initially; then add T10 dismissal and A14 loaded-save joining through one lifecycle model.
5. Choose an inventory foundation and add T05 burst invariants, A01 native-item rules and one A11 UI guard. Redesign A09 under the same transaction model. Combine A16 with mandatory b920e9e and merchant identity/locks. Establish conservation before proceeding.
6. Port A02–A05/A07 intents as coherent channels with HostIntent retry/idempotency/reset. Retain Savas host-only native production and research book-cost authority.
7. Combine T07/B06 own-hit rules, A10 limbs, A12 signed medical/bandage behavior, A08 carry/assassination, then B08 NPC mirrors with Savas squad-combat guards. Bring diagnostics before fixes and use feature-flag A/B checks.
8. Unify saving: atomic validation/staging → A06 inventory fence and B05 metadata → load-specific READY → A13 compressed transfer → commit/ACK → resume by B07/A15 pause reason. Validate Unicode/backups and T08 autosave-stream exclusion.
9. Finish UI/installer/update/Workshop; tune WAN/100 Hz after wire/gameplay invariants stabilize. Validate DLL pairs and reject incompatible foreign builds.
