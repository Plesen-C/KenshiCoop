# KenshiCoop: аудит публичной сети форков на 2026-11-01

> Исторический снимок до создания Plesen-C/KenshiCoop. Число 43 относится к моменту исследования, а не к текущему размеру сети.

Временное окно: с **2026-10-01 00:00:00 UTC** до момента проверки **2026-11-01 11:14 UTC**. Это трактовка просьбы «обновление не старше месяца»; время в таблицах — UTC. Даты API совпадают с датой окружения.

Проверено **43 публичных форка**: 41 прямой форк nhoral/KenshiCoop и 2 форка второго уровня. **9** имеют свежий `pushed_at`; у **8** из них обнаружены собственные коммиты в одной из публичных веток. Ещё **5** попадают в окно только по `updated_at`/созданию, без свежего push.

`updated_at` описывает обновление объекта репозитория и не доказывает изменение кода. `pushed_at` отражает push в репозиторий, но он может относиться к дополнительной ветке, тегу либо синхронизации. Поэтому отдельно проверены вершины main и дополнительных веток свежих кандидатов. «Собственный коммит» здесь означает октябрьский/ноябрьский коммит продолжения форка, созданный после последнего push исходника от 10 августа; это не оценка качества и не гарантия работоспособности.

## Обзор исходного nhoral/KenshiCoop

Проверка выполнена 1 ноября 2026 года. Это обзор исходников, документации и публичной истории, без запуска Kenshi и без сборки Windows DLL.

- Экспериментальный кооператив для Kenshi 1.0.65 Steam: C++ DLL через RE_Kenshi/KenshiLib; ENet/UDP либо Steam P2P. Исходный проект рассчитан на двух игроков. Хост управляет миром, игроки — своими отрядами; предусмотрена репликация NPC, боя, инвентаря, построек, общего кошелька и передача сохранений. [README](https://github.com/nhoral/KenshiCoop/blob/main/README.md).
- Последний коммит `main`: `5a761e19`, 10.08.2026 19:51 UTC. Последний релиз — [v0.51](https://github.com/nhoral/KenshiCoop/releases/tag/v0.51), 10.08.2026 19:52 UTC; wire protocol 55. В релизе прямо указано: обе стороны должны использовать одинаковую версию, даже v0.50 и v0.51 не соединяются. [Коммит](https://github.com/nhoral/KenshiCoop/commit/5a761e19a4184b42315e96ea7e92e3c1403d54db).
- Код разделён на `core`, `game`, `net`, `sync`, `test`. Изменения игрового состояния выполняются через главный поток. Есть отдельные тесты протокола, симулятор, тесты Steam-туннеля и сценарии двух игровых клиентов; это инфраструктура проверки, а не подтверждение успешного прогона в этой сессии. [Plugin.cpp](https://github.com/nhoral/KenshiCoop/blob/main/src/plugin/Plugin.cpp), [verify.ps1](https://github.com/nhoral/KenshiCoop/blob/main/scripts/verify.ps1).
- Сборка требует Windows, Visual C++ 2010/v100 x64, KenshiLib и патченного ENet. Документация сборки неполна: `docs/BUILD_SETUP.md` перенаправляет на отсутствующий в текущем дереве `resources/BUILD_SETUP.md`. API reference также сохраняет разделы уже удалённого транспортного стека, о чём сам предупреждает. [Проект](https://github.com/nhoral/KenshiCoop/blob/main/src/plugin/KenshiCoop.vcxproj), [инструкция](https://github.com/nhoral/KenshiCoop/blob/main/docs/BUILD_SETUP.md), [API reference](https://github.com/nhoral/KenshiCoop/blob/main/docs/API_REFERENCE.md).
- Стабильность игрового сеанса не подтверждена: автор помечает мод WIP; в открытых issues есть сообщения о рассинхронизации и потере предметов. Важно различать оригинал и продолжения: [issue #90](https://github.com/nhoral/KenshiCoop/issues/90) уже обсуждает Savas07/ximery4, поэтому оно само по себе не доказывает наличие той же ошибки в каждой версии оригинала.
