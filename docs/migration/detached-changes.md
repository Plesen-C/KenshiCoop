# Change map for separate KenshiCoop continuations

Reviewed November 1, 2026. Static comparison of real source with upstream `5a761e19` and Savas `58514ea3`; donor code, tests, installers and DLLs were not executed. Implementation presence does not establish gameplay correctness. Some kotetsyy work shares Brandon ancestry and must be deduplicated.

## Sources and reproducibility

Local downloaded archives, extracted trees and intermediate diffs are not included in this fork. [changes-detached.json](changes-detached.json) records snapshots, archive SHA-256 values, extraction checks and findings. Paths beginning agent-detached/... identify local research copies; src/... paths refer to the named donor.

Snapshots: kotetsyy `61b92802`, Vep124 `d841528e`, Savas `58514ea3`, nhoral `5a761e19`, LRaverdy `ce9487bc`. Provod uses the exact [KenshiCoop-update66-source.zip asset from .5.3.1](https://github.com/ProvodD-min/KenshiCoop-private-squads/releases/download/v0.51-private-squads.5.3.1/KenshiCoop-update66-source.zip), SHA-256 **8f4977f096c701c62689546a2f9f09a9daaee502194806d68ac363f8f311a7f0**. It contains KenshiCoop/, KenshiLib/ and vendor64-tests/. No README was substituted for the source asset.

Before extraction, paths were checked against absolute names, traversal, colons, symlinks and case-fold collisions. Entry count and uncompressed size were bounded. Files were extracted as ordinary mode-0644 files and not executed. Archives were retained locally.

## LRaverdy: architectural alternative, unconfirmed lineage

No root LICENSE was found and nhoral ancestry/attribution was not established. Transfer compatibility is unresolved; use as architectural reference without importing its code until provenance and permissions are established.

The implementation differs substantially: CMakeLists.txt:9 selects C++20, v2022/static CRT; common/include/kc/protocol.h:24 defines magic KCOP, protocol 36, maximum eight and a separate Msg enum. Bounded Reader/Writer replaces upstream packed POD. common/src/session_*.cpp separates game-independent domain/session logic; plugin/ uses direct engine 1.0.68 bindings, MinHook, ImGui/DX11 and ENet rather than the KenshiLib/RE_Kenshi ABI.

Host runs one authoritative simulation. Clients send Command/InvOp/DialogReply/SquadRequest and render host state. Host validates owners through session_actions.cpp/session_authority.cpp/session_items.cpp; it assigns netIds/Bind and provides compressed world streaming/Ready, separate snapshot/vitals channels, roster and editor queue. This differs from the source lineage’s player-owned squad simulations plus host world. Adopting it means a client-command redesign, not a normal Replicator merge.

Useful reference subjects: explicit domain/session separation, bounded codecs, authoritative command replay, version/mod gates, join/editor queues, dialogue ownership, netId mapping, compression and host tools. Its live behavior was not tested here.

## Recommended base and sequence

Savas585 is the practical first integration base when preserving plugin/v100/KenshiLib and porting fixes incrementally. It already has shared-pool per-owner ACK, durable squads, N-player lobbies and fixes through October 23. Kotetsyy becomes a reasonable primary base if transport/UI replacement is the first objective and the work includes four-DLL ABI/package recovery, payload framing and reverse-porting Savas gameplay fixes. Simultaneous wire/transport/UI/economy replacement makes regressions harder to isolate.

1. Freeze PlayerId/ConnectionId/WorldId, item identity/provenance, actor/merchant/fixture identity, authority, transaction IDs and shared/private campaign policy. Separate transport, gameplay and UI options; mutually exclusive policies have one active handler.
2. Correct lifecycle/cache reset and fixture-fabrication prerequisites from the core map. Define reset/load/disconnect hooks and resource lifetimes. Newer patches are not automatically correct.
3. Define versioned family/build/schema identity before full payload parsing, one enum allocation (49–57 and 250 currently collide), codec adapters and explicit old-wire rejection. Preserve save migration independently of mixed-wire compatibility.
4. Port isolated refusal/latch behavior without FNV authentication, pure admission/lock revisions, charged-item reuse/rollback and reproduction-matched carry/medical fixes. Each requires a failing baseline case and focused behavior change.
5. Select one inventory/commerce coordinator: bounded complete snapshots with parent/grid/metadata, transaction journal, exact actor ACK, pricing/stock authority and one Economy service. Preserve the other implementations’ useful invariants/tests.
6. Save an atomic cut of all domain states/sidecars with world epoch, versioned manifest/checksum and explicit shared→private allocation/migration. Test rollback/corruption/rejoin; changing flags must not silently reinterpret another .dat format.
7. Route Vep browser/Savas friend lobby through one SessionController; adapt Kotets UI. Remove fixed-two/max-four UI assumptions when supporting eight/nine.
8. Add optional GNS late while retaining ENet and identical DTO/transaction/lifecycle semantics. Validate reliable ordering, coalescing, bulk starvation/backpressure, Steam callback thread confinement, generation retirement, package recovery and provider ABI3 lifetime. Add the four-DLL updater after pinning the runtime manifest.
9. Add procedural camp beds after identity/world readiness. Keep environment items experimental. Canonical identity foundation is a separate milestone; LRaverdy remains reference or a separate rewrite pending provenance/permissions.

Future checks, not executed: concurrent take/drag/corpse/trade conservation; complete/partial snapshots and 4096-item bounds; exact wallet/stock ACK and crash mid-checkpoint; merchant restock/unload/rekey; carried-body bed/floor/landing; lockpick/rejoin/stale packets;2/3/4/8 players and late join; reordered logical-identity reconnects; save rollback/corrupt/missing sidecars; Steam/direct UDP on both backends. Validate shared and private modes independently.
