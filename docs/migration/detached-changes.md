# Карта изменений отдельных продолжений KenshiCoop

Проверено 01.11.2026. Это статический разбор реальных исходников и план переноса; репозиторный код, тесты, установщики и DLL не запускались. Наличие реализации не означает, что её корректность подтверждена в игре. Группы ниже описывают отличия от nhoral `5a761e19` и от Savas `58514ea3`; общие с Brandon изменения необходимо дедуплицировать по истории, а не считать независимыми разработками.

## Источники и воспроизводимость

Исследование выполнено на локальных снимках исходников. Архивы, распакованные деревья и промежуточные diff в этот форк не включены. Идентификаторы снимков, SHA-256 архивов, параметры безопасного извлечения и выводы сохранены в [changes-detached.json](changes-detached.json). Пути `agent-detached/...` ниже обозначают локальные исследовательские копии; пути `src/...` относятся к соответствующему донору.

Снимки: kotetsyy `61b92802`, Vep124 `d841528e`, Savas `58514ea3`, nhoral `5a761e19`, LRaverdy `ce9487bc`. Provod — точный asset [KenshiCoop-update66-source.zip из .5.3.1](https://github.com/ProvodD-min/KenshiCoop-private-squads/releases/tag/v0.51-private-squads.5.3.1), SHA-256 **8f4977f096c701c62689546a2f9f09a9daaee502194806d68ac363f8f311a7f0**; архив содержит `KenshiCoop/`, `KenshiLib/`, `vendor64-tests/`. Ни один source asset не подменялся README.

Перед извлечением проверены все пути (нет абсолютных, `..`, `:`, symlink или регистровых коллизий), число записей и суммарный размер ограничены; извлечение выполнено собственным Python-кодом с правами обычных файлов `0644`. Исходные zip были сохранены в локальном исследовательском архиве. Извлечённые файлы не исполнялись.

## LRaverdy: архитектурная альтернатива, не подтверждённый fork

Префикс `agent-detached/lraverdy/KenshiCoop-master/`. В корне **нет LICENSE**, ancestry/атрибуция nhoral не установлены; не считать AGPL-совместимость переноса доказанной. Использовать для сравнения архитектуры до выяснения прав и происхождения, без копирования кода.

Код заметно другой: `CMakeLists.txt:9` C++20, v2022/static CRT; `common/include/kc/protocol.h:24` magicKCOP, protocol36, max8, separate Msg enum, bounded Reader/Writer в wire.h вместо packed upstream POD. `common/src/session_*.cpp` — game-independent domain/session; `plugin/` — прямые engine bindings1.0.68, MinHook, ImGui/DX11 и ENet. KenshiLib/RE_Kenshi ABI не является его основой.

Host запускает единственную authoritative simulation. Клиент посылает Command/InvOp/DialogReply/SquadRequest и визуализирует host state; owner validation проходит на host (`common/src/session_actions.cpp`, `session_authority.cpp`, `session_items.cpp`), есть host-assigned netIds/Bind, compressed world stream/Ready, отдельные channels snapshot/vitals, player roster и editor queue. Это противоположно исходному **каждый владеет симуляцией своего squad + host world**. Перенести отдельные команды/ideas можно только через новый client-command architecture; обычный merge Replicator невозможен.

Полезно как reference для: explicit session/domain separation, bounded codec, host-authoritative command replay, version/mod compatibility gate, join/editor queue, dialogue ownership, netId mapping, compression и host tools. Это не основание заявлять исправленными его заявленные функции: native live behavior не запускался.

## Рекомендация по базе и безопасному порядку совмещения

**Savas585 — практичная база первой интеграции**, если цель — сохранить исходный plugin/v100/KenshiLib ecosystem и быстро переносить исправления. У него уже shared-pool per-ownerACK, persistent player/squad data, N-player Steam lobby и исправления до23.10. Kotets — разумная самостоятельная база лишь если **переработка транспорта/UI — цель первого этапа**, а бюджет включает 4-DLL ABI/package recovery, новый payload framing и перенос gameplay Savas обратно. Одновременный wire+transport+UI+economy rewrite затруднит локализацию регрессий.

1. **Заморозить domain contracts до merge**: logical PlayerId/ConnectionId/WorldId, item identity/provenance, actor/merchant/fixture identity, owner authority, transaction IDs и shared/private campaign mode. Отдельно сохранить transport/campaign/UI options; mutually exclusive gameplay modes должны быть selectable, а не выполнять два handler одновременно.
2. **Закрыть prereqs исходной базы**: Ximery lifecycle/cache reset и доказательство conservation fixture fabrication (основной агент нашёл эти проблемы); unified session reset/load/disconnect hooks и resource lifetimes. Не объявлять эти ветви автоматически безопасными только потому что новее.
3. **Новый versioned envelope/schema**: family/build/schema hash+capabilities до чтения полного payload, единый enum allocation (49..57 и250 сейчас конфликтуют), codec adapters для общих DTO; явное отклонение старых несовместимых клиентов. Сохранить возможность читать старый **save**, не обещать mixed-wire clients.
4. **Ранние isolated fixes**: refusal reason/latch из Vep без FNV-auth; pure admission/door revisions; provenance/charged-item reuse/rollback из Provod; matched Savas carry/medical fixes. Для каждой — воспроизводимый failing case на базе и одно изменение поведения.
5. **Единая inventory/commerce модель**: complete bounded snapshot framing+parent/grid/metadata; host transaction journal, actor exact ACK, price/stock authority и один Economy service. Сравнить три commerce реализации, выбрать одну основу; переносить остальные полезные invariants/tests. После этого private-wallet и faction modes поверх общего domain/persistence interface.
6. **Сейвы как согласованный cut**: captures всех domain states и sidecars с world epoch; versioned campaign manifest и checksum, migration/shared→private allocation, rollback/corruption/rejoin. Откат feature flag не должен молча читать чужой формат .dat.
7. **Discovery/UI**: browser Vep и friend lobby Savas к одному SessionController; Kotets UI через adapter, один selected frontend. Не оставлять fixed2/max4 в UI при общем лимите8/9.
8. **Late optional GNS transport/backend**: сохранить ENet baseline, те же DTO/transactions/lifecycle; отдельно проверить reliable ordering, coalescing, bulk starvation/backpressure, Steam callback game-thread confinement, generation retirement, package recovery и ABI3/provider lifecycle. Переносить 4-DLL updater только после фиксации итогового runtime manifest.
9. **Procedural extensions**: camp beds после identity+world readiness; environment-item scopes пока эксперимент. Canonical identity foundation — отдельный architecture milestone. LRaverdy — reference/отдельный rewrite, не patch source без установленной лицензии.

Необходимые будущие проверки (план, не выполнено): inventory conservation при simultaneous take/drag/corpse/trade, full/partial snapshots и4096 limits, exact wallet stock ACK и crash mid-cut, merchant restock/unload/rekey, carried body bed/floor/landing, lockpick/rejoin/stale packets,2/3/4/8 игроков и late join, logical identity reconnect в другом порядке, save rollback/corrupt/missing sidecars, Steam/directUDP обеих backend implementations. Shared и private modes проверяются раздельно; успех одного не подтверждает другой.
